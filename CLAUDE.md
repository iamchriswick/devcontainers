# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Branch-per-concern layout

This repo (`iamchriswick/devcontainers`) keeps each concern on its own long-lived branch, checked out as sibling worktrees of a bare clone at `../.bare`:

| Branch | Worktree | Holds |
| --- | --- | --- |
| `main` | `../main` (here) | Release orchestration workflows only; no feature or template source |
| `features` | `../features` | Dev Container Features in `src/<id>/`, tests in `test/<id>/` and `test/_global/` |
| `templates` | `../templates` | Dev Container Templates in `src/<id>/`, smoke tests in `test/` |
| `config` | `../.config` | Dotfiles/helper config (zsh, starship, eza, delta, Claude settings), versioned by release-please |

Edit a concern in its own worktree. The branches share no history of each other's files, so merging between them is never the move.

## Workflows on `main`

Every workflow here is manual (`workflow_dispatch`), named `TEST: ...`, and checks out another branch to do its work:

- `release.yaml`: guarded to `main`; checks out `features`, validates `./src`, packages with `devcontainer features package`, and per feature creates a pinned release `feature_<id>_v<version>` plus a rolling `feature_<id>` release that is deleted and re-pointed each time. An existing versioned release is skipped, so bump `version` in `devcontainer-feature.json` to ship.
- `release_config.yaml`: guarded to `main` + dispatch; runs release-please (`release-type: simple`) against `config`, skipping PR creation.
- `publish.yaml`: publishes Features to GHCR, but is guarded to `refs/heads/features` while the file lives only on `main`. A dispatch runs the workflow file from the chosen ref, so it fires only once a copy exists on `features`.

Generated-docs PRs from both feature workflows target `features`.

## Testing Features

Run from the `features` worktree with `@devcontainers/cli` installed (mirrors `features/.github/workflows/test.yaml`):

```sh
devcontainer features test -f <id> -i debian:latest --skip-scenarios .   # autogenerated test vs one base image
devcontainer features test -f <id> --skip-autogenerated --skip-duplicated .   # scenarios.json only
devcontainer features test --global-scenarios-only .
```
