# Template metadata and options

Type: grilling
Status: resolved
Blocked by: 06

## Question

What goes into `devcontainer-template.json` for `typescript-node`: `id`, `version`, `name`, `description`, and for each option (`imageVariant`, `name`, `claudeConfigVolumeName`, `claudeConfigDir`) its type, `proposals` or `enum`, and default? How is `python` made optional, given template options only substitute text and cannot add or remove a `features` entry (https://containers.dev/implementors/templates/)?

## Proposal

- `id: typescript-node`, `version: 1.0.0`, `name: "TypeScript & Node.js with Claude Code"`, `description` one line.
- `imageVariant`: string, proposals `["5-24-trixie"]`, default `5-24-trixie` (the tag in `~/TMP/.devcontainer/devcontainer.json`).
- `name`: string, default `typescript-node`; used for `name` and `runArgs: ["--name", "${templateOption:name}"]`.
- `claudeConfigVolumeName`: string, proposals and default as in `~/TMP/.devcontainer/devcontainer-template.json` (`devcontainers-claude-code-config`, `claude-code-config`).
- `claudeConfigDir`: per "claudeConfigDir default value".
- `python`: not in the Template's `features`; the user adds it from the Feature list when wanted. `github-cli` is in the Template's `features`.

## Answer

Source: user's answers (audit session, 2026-11-01/02), with the facts below.

- `id: typescript-node`, name "Node.js & TypeScript", `version: 0.1.0`, description "Develop Node.js based applications in TypeScript. Optional Features set up zsh, Starship, git-delta, eza and Claude Code."
- Image `mcr.microsoft.com/devcontainers/typescript-node:5-${templateOption:imageVariant}`, the official Template's pattern. `imageVariant` proposals: `trixie` (default), `26-trixie`, `24-trixie`, `22-trixie`. Debian trixie only.
  - Facts: in the mcr tag list (https://mcr.microsoft.com/v2/devcontainers/typescript-node/tags/list) the `5-*` tags are 22, 24 and 26 on trixie and bookworm, plus bullseye for 22 and 24. `latest` and `5-trixie` carry Node 24.22.1 (Microsoft's default), `5-26-trixie` carries Node 26.12.1 (image config, read 2026-11-01). Node LTS lines: 26 (LTS since 2026-10-28), 24, 22; 20 ended 2026-04-30 (https://github.com/nodejs/Release). trixie = Debian 13 (current stable), bookworm = Debian 12 (LTS-only since 2026-06-11), bullseye = Debian 11 (support ended) (https://wiki.debian.org/LTS).
- The proposals are regenerated by a step in the release workflow on `main` from the mcr tag list (latest + the last LTS lines), because Template options are static JSON.
- `name`: default `${containerWorkspaceFolderBasename}`, used for `name` and `runArgs: ["--name", "${templateOption:name}"]`. Facts: the spec allows it in any property (https://containers.dev/implementors/json_reference/#variables-in-devcontainerjson); `${localWorkspaceFolderBasename}` is not set when cloning into a container volume (https://github.com/microsoft/vscode-remote-release/issues/6160).
- No user option and no `containerUser`: the container runs as the image's user and Features use `_REMOTE_USER` / `_REMOTE_USER_HOME`. Facts: the CLI passes `containerUser` to `docker run -u` and never creates the user (devcontainers/cli `src/spec-node/singleContainer.ts:360`, `scripts/updateUID.Dockerfile`); Docker requires a named user to exist (https://docs.docker.com/engine/containers/run/, "User").
- `claudeConfigVolumeName` and `claudeConfigDir` are dropped: Claude config is in the `claude-code-config` Feature (issue 08).
- `github-cli` is in the Template's `features`; `python` is not listed, the user adds it in the Feature picker.
